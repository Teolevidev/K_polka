# Google Books: как забирать данные и обложки

Разбор от 2026-09-09. Все, что здесь написано, либо проверено запросом,
либо помечено как непроверенное.

## 1. Ключ обязателен. Это не «желательно»

В коде было написано, что `GOOGLE_BOOKS_API_KEY` лишь снимает лимиты.
Это неверно. Запрос без ключа:

```
$ curl -sS https://www.googleapis.com/books/v1/volumes/jBiIQlevopYC
```

отвечает **429** и в теле:

```json
"message": "Quota exceeded for quota metric 'Queries' and limit
            'Queries per day' of service 'books.googleapis.com'",
"metadata": { "quota_limit": "defaultPerDayPerProject",
              "quota_limit_value": "0" }
```

Ключевое здесь - `quota_limit_value: 0`. Дневная квота анонимных
обращений равна нулю: источник без ключа не работает вовсе, а не
работает медленнее. До сих пор это выглядело как «Google иногда молчит»,
потому что ошибку источника поиск проглатывал.

**Следствия, которые внесены в код:**

- `requireApiKey()` бросает `GoogleBooksNotConfiguredError`, если ключа
  нет;
- поиск отделяет «источник не настроен» от «источник не ответил» и
  говорит об этом разными словами: первое чинит администратор за минуту,
  второе проходит само.

## 2. Что API отдает на самом деле

Ответ `GET /volumes/{id}` состоит из трех блоков. Раньше читался только
первый:

| Блок | Что внутри | Читали раньше |
|------|-----------|---------------|
| `volumeInfo` | название, авторы, издательство, дата, объем, ISBN, жанры, язык, рейтинг, обложки, серия, формат | частично |
| `saleInfo` | продается ли, цена, ссылка на покупку, электронное ли издание | нет |
| `accessInfo` | предпросмотр, EPUB, PDF, ссылка на читалку, общественное достояние | нет |

Именно из `saleInfo` и `accessInfo` на сайте Google собрана вкладка
«Получить книгу». Теперь они разбираются в `src/lib/books/google-volume.ts`
и показываются блоком «Получить книгу» на странице книги.

Из `volumeInfo` добавились: `publisher`, `printType`, `seriesInfo`,
`canonicalVolumeLink`, `averageRating`/`ratingsCount` (на странице книги
их не было), `printedPageCount` как запасной вариант для объема.

Описание приходит **с HTML внутри** - без очистки читатель видит теги в
аннотации. Чистится через `htmlToPlainText`.

## 3. Обложки: почему прямая ссылка не годится

Три причины, по которым `imageLinks` нельзя отдавать в браузер как есть.

1. **Провайдер.** У части российских провайдеров `google.com` режется по
   SNI - TLS не устанавливается вовсе. Это наблюдалось на машине
   заказчика: `openssl s_client` к google.com обрывается на ClientHello.
   У такого читателя обложка не загрузится никогда.
2. **Кеширование.** Через свой домен картинка кладется в CDN на год.
   Полка в двадцать книг - двадцать обращений в Google на всю аудиторию,
   а не на каждого читателя.
3. **Выбор размера.** У тома несколько вариантов картинки, и какие из
   них существуют - у каждого тома по-разному. Перебирать в браузере
   значит показывать читателю мигающие битые картинки.

### Решение: `/api/cover`

Маршрут `src/app/api/cover/route.ts` принимает **не произвольный адрес**,
а зацепки:

```
/api/cover?g=<googleVolumeId>&isbn=<isbn>&u=<готовый адрес>&size=s|m|l
```

и перебирает варианты по порядку, пока не получит настоящую картинку.
Открытым прокси при этом не становится:

- `u` принимается только для хостов из белого списка
  (`books.google.com`, `books.googleusercontent.com`,
  `covers.openlibrary.org`);
- `g` и `isbn` проверяются регулярным выражением, адрес собирается по
  шаблону на сервере;
- ответ отдается, только если `content-type` начинается с `image/`.

Отдельная тонкость: **Google на отсутствующую обложку отвечает 200** и
отдает крошечную пустую картинку. Поэтому ответ короче килобайта
считается заглушкой и не засчитывается. У OpenLibrary та же беда, и там
она лечится параметром `default=false` - без него приходит серая
заглушка с кодом 200 вместо честной 404.

Заворачивание живет в одном месте - в компоненте `BookCover`
(`proxiedCoverUrl`). Поэтому обложка идет через маршрут независимо от
того, откуда взялся адрес: из поиска, из базы, из витрины главной или из
AI-рекомендации.

## 4. Замеры обложек: сколько на самом деле дает каждый zoom

Замерено на томе `jBiIQlevopYC` («Спектр», ссылка заказчика). Размеры
прочитаны из заголовков самих файлов, а не из `Content-Length`:

| Вариант | Пиксели | Размер |
|---------|---------|--------|
| `zoom=1`, `zoom=5`, `thumbnail`, `smallThumbnail` | 128x194 | 12 КБ |
| `zoom=2`, `small` | 300x454 | 29 КБ |
| `zoom=3`, `medium` | 575x871 | 88 КБ |
| `zoom=4`, `large` | 800x1211 | 143 КБ |
| `zoom=0`, `zoom=6`, `extraLarge` | 1744x2641 | 532 КБ |

Три вывода, каждый поменял код.

**1. `zoom` не монотонный.** Больше значение не значит больше картинка:
`zoom=0` дает максимум, `zoom=5` - минимум. В первой версии маршрута
стояло `[3, 2, 1]` для крупного размера - то есть 575 точек там, где
доступно 800. Исправлено на замеренную лестницу.

**2. Токен `imgtk` не нужен.** Адреса из `imageLinks` несут длинный
токен, а собранные по шаблону без него отдают ту же картинку тем же
размером. Значит, обложку можно запросить, ни разу не сходив в API, и
сохраненная ссылка не протухнет вместе с токеном. Собранный адрес теперь
идет первым, готовый - запасным.

Заодно у адресов из `imageLinks` стоит `edge=curl` - загнутый уголок
страницы, который мы все равно срезаем кадрированием. Он же добавляет
2 КБ: 14677 против 12420 байт на одной и той же картинке.

**3. Размер надо выбирать, а не брать максимум.** 532 КБ на обложку в
ленте из восьми книг - это 4 МБ на один экран. Поэтому:

| Где | Размер | zoom | Что получится |
|-----|--------|------|---------------|
| карточка в ленте (~150 точек) | `s` | 2 | 300x454, 29 КБ |
| по умолчанию | `m` | 3 | 575x871, 88 КБ |
| страница книги (~200 точек) | `l` | 4 | 800x1211, 143 КБ |

`zoom=0` в приложении не используется: он в три с лишним раза тяжелее
`zoom=4`, а на экране разницы не видно.

## 5. Что API не отдает

По этому тому не пришло:

- **рейтинга нет вовсе** - ни `averageRating`, ни `ratingsCount` в ответе
  не оказалось. Значит, звездочки Google будут показываться далеко не у
  всех книг, и своя оценка клуба тем важнее;
- **ссылки на покупку нет**: в `saleInfo` только `country`, `isEbook`,
  `saleability`. Кнопка «Купить» просто не рисуется;
- **серии нет**: `seriesInfo` отсутствует, хотя «Спектр» входит в цикл.

Зато есть `epub`, `pdf` и `webReaderLink` - фрагмент читается в читалке
Google.

**Жанры приходят путями BISAC на английском:**
`"Fiction / Science Fiction / Space Opera"`. Показывать их как есть на
русской странице нельзя. На сайте Google жанры выглядят иначе
(«Научная фантастика»), но берутся из их графа знаний и через API
недоступны. Поэтому переводим сами: `src/lib/books/genres.ts` берет
самый точный уровень пути и ищет его в словаре, поднимаясь выше, если
уровень незнаком или пустой («General»).

## 6. Что осталось непроверенным

Замеры сделаны на одном томе. Не проверено, одинаковая ли лестница
`zoom` у всех книг - у сканированных изданий и у книг без электронной
версии она может отличаться. Код от этого не ломается: он перебирает
варианты по порядку и берет первый настоящий, а размеры лишь задают
предпочтение.

Проверить на другом томе - тем же маршрутом:

```
/api/debug/volume?id=<идентификатор тома>
```

Маршруты `/api/debug/volume` и `/api/debug/search-probe` временные и
подлежат удалению, как только вопрос закрыт. Секретов они не отдают:
ключ уходит в строке запроса и обратно не возвращается.
