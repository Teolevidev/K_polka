# Настройка локальной работы с Claude Code

Пошаговая инструкция для macOS. Цель: поднять проект на своей машине и
дать Claude Code возможность работать с ним самостоятельно.

Зачем это нужно. В облачных сессиях у Claude Code жесткая сетевая
политика: часть внешних API недоступна, приложение вживую не посмотреть.
Локально этих ограничений нет, поэтому он сможет сам ходить в Google
Books и OpenLibrary, запускать приложение, смотреть на него в браузере
и проверять правки на живых данных, а не по вашим скриншотам.

Все команды набираются в **Терминале**: Cmd+Space, набрать «Терминал»,
Enter. Каждую строку вводим отдельно и жмем Enter.

---

## Шаг 1. Node.js

Проверяем, стоит ли:

```
node -v
```

Если ответил номером версии 20 или выше (например `v22.14.0`) - готово,
идем дальше.

Если написал `command not found` или версия ниже 20: скачайте установщик
с [nodejs.org](https://nodejs.org), кнопка **LTS**, и пройдите установку
обычными «Далее». Потом закройте Терминал, откройте заново и проверьте
`node -v` еще раз.

## Шаг 2. Git

```
git --version
```

Если Git не установлен, macOS сама предложит поставить Command Line
Tools - согласитесь и подождите. Это несколько минут.

## Шаг 3. pnpm

Проект собирается пакетным менеджером pnpm, не npm.

```
npm install -g pnpm@9
pnpm -v
```

Вторая команда должна ответить версией, начинающейся на 9.

## Шаг 4. Забрать проект

Кладем в домашнюю папку:

```
cd ~
git clone https://github.com/Teolevidev/K_polka.git
cd K_polka
```

Если папка уже есть, вместо клонирования просто зайдите в нее:

```
cd ~/K_polka
git pull
```

## Шаг 5. Установить зависимости

```
pnpm install
```

Займет полминуты. Появится папка `node_modules` - так и должно быть,
в git она не попадает.

## Шаг 6. Файл с ключами

Проекту нужны ключи от Supabase и внешних сервисов. Они лежат в файле
`.env.local` в корне проекта. Этот файл **намеренно не хранится в git**
и на вашей машине его пока нет - его надо создать.

Открыть его в редакторе:

```
open -e .env.local
```

Если файла нет, команда пожалуется. Тогда сначала создайте пустой:

```
touch .env.local
open -e .env.local
```

Что вписать - смотрите файл `.env.example` в корне, там перечислены все
переменные с пояснениями. Значения берутся так:

| Переменная | Где взять |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Там же → Project API keys → **anon public** (длинный, начинается с `eyJ`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Там же → **service_role**. Секретный, наружу не отдавать |
| `DATABASE_URL` | Supabase → Project Settings → Database → Connection string (URI) |
| `GOOGLE_BOOKS_API_KEY` | Google Cloud Console → Credentials |
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys |

Если проект уже настроен в Vercel, все это можно вытянуть одной командой
после шага 9: `vercel env pull .env.local`.

Сохраните файл: Cmd+S, потом Cmd+Q.

## Шаг 7. Проверить, что проект живой

```
pnpm typecheck
pnpm test
pnpm dev
```

Последняя команда запускает приложение. Откройте
[localhost:3000](http://localhost:3000) в браузере. Остановить сервер -
Ctrl+C в Терминале.

## Шаг 8. Поставить Claude Code

```
npm install -g @anthropic-ai/claude-code
```

Запустить из папки проекта:

```
cd ~/K_polka
claude
```

При первом запуске попросит войти в аккаунт - откроется браузер. Дальше
пишете в терминал так же, как в веб-версии.

Актуальная инструкция, если команда не подойдет:
[claude.com/claude-code](https://claude.com/claude-code).

## Шаг 9. Vercel CLI (по желанию)

Дает Claude Code возможность смотреть переменные окружения, логи и
пересобирать деплои, не открывая браузер.

```
npm i -g vercel
vercel login
cd ~/K_polka
vercel link
```

`vercel link` спросит, к какому проекту привязать папку - выберите
существующий `kpolka`.

После этого станут доступны:

```
vercel env ls                    # какие переменные заданы и для каких окружений
vercel env pull .env.local       # стянуть их к себе
vercel logs <адрес деплоя>       # логи
vercel redeploy                  # пересобрать
```

Учтите: `vercel login` дает с этой машины полный доступ к вашему
аккаунту Vercel.

## Шаг 10. Разрешения

По умолчанию Claude Code спрашивает согласия почти на каждую команду.
Это быстро утомляет. Скажите ему в первой же локальной сессии:

> настрой разрешения, чтобы не спрашивать на каждой мелочи

Он посмотрит, какие команды использует чаще всего, и сложит безопасную
рутину (тесты, проверка типов, чтение файлов, статус git) в список
разрешенного. Подтверждения останутся там, где они действительно нужны.

Посмотреть и поправить список потом: команда `/permissions`.

## Что делать в первой локальной сессии

Скажите Claude Code:

```
прогони node scripts/probe-search.mjs "Пушкин" и разберись,
отвечает ли Google Books
```

Это тот вопрос, который в облачной сессии закрыть не получалось.

## Где Claude Code остановится и спросит

Даже с полным доступом он не станет без вашего слова: пушить в `main`,
менять продовые переменные, применять миграции к боевой базе, удалять
данные. Такие вещи он покажет и дождется подтверждения.
